# HOW TO

This file provides a full example on how to use this project, with a private provider and module.

## Deployment

1. Clone the repo:

``` bash
git clone https://github.com/asensionacher/private-tf-platform.git
```

2. Create random passwords for encryption and Postgres:

``` bash
openssl rand -base64 32 # For encryption
openssl rand -base64 24 # For Postgres password
```

3. Copy `.env.example` to a new file called `.env` and replace the placeholder values with the keys generated by `openssl rand`.
4. Add a `REGISTRY_HOST` value in `.env` if you want a different one, or keep the default (in this example we will use `registry.lan`).
5. Create HTTPS certs if you don't have them by running [gen-certs.sh](./scripts/gen-certs.sh). These certificates will be saved in the `nginx/certs` folder.
6. Add the hostnames to your `/etc/hosts` file (Linux/macOS) or `C:\Windows\System32\drivers\etc\hosts` (Windows), where `server-ip` can be `127.0.0.1` or the private IP of the machine running nginx. This should be done on the machine that will run `Terraform` or `OpenTofu`:

```
server-ip registry.lan  api.registry.lan  tf.registry.lan
```

7. Start Docker Compose using:

```bash
docker compose up -d --build
```

8. Once it finishes, open a browser and navigate to [https://registry.lan](https://registry.lan).

## Using the platform

Now we will show an example on how to use a private provider and a private module.

1. Create a private namespace for your org in Namespaces. We will create one called `my-org` and keep it private.
2. Create a new API key and save it to the clipboard.
3. On the machine that will run `Terraform` or `OpenTofu`, create a file called `~/.terraformrc` (Terraform) or `~/.tofurc` (OpenTofu) with the following content, where `<api-key-from-the-web-ui>` is the key you copied and `registry.lan` is your `REGISTRY_HOST`:

```hcl
host "api.registry.lan" {
  services = {
    "providers.v1" = "https://api.registry.lan/v1/providers/"
    "modules.v1"   = "https://api.registry.lan/v1/modules/"
  }
}

credentials "api.registry.lan" {
  token = "<api-key-from-the-web-ui>"
}
```

4. Create a new provider with the following values:
    1. Namespace: my-org (or your new private namespace).
    2. Provider name: terraform-provider-random
    3. Git repository URL: https://github.com/hashicorp/terraform-provider-random
5. Once the tags are synced, click the visibility toggle (eye icon) next to version 3.9.0 to publish it.
6. Click on the version (now shown in green) and upload the provider binary that matches the OS and architecture of the machine running Terraform. In this example that is `Linux AMD64`, downloadable from [terraform-provider-random_3.9.0_linux_amd64.zip](https://releases.hashicorp.com/terraform-provider-random/3.9.0/terraform-provider-random_3.9.0_linux_amd64.zip).
7. Create a new module with the following values:
    1. Namespace: my-org (or your new private namespace).
    2. Module Name: naming
    3. Provider: azure
    4. Git repository URL: https://github.com/asensionacher/terraform-azurerm-naming
8. Go inside the module and click the visibility toggle (eye icon) next to tag `v0.0.1` to publish that module version.
9. Create a folder on your machine with the following files:

```hcl
# terraform.tf
terraform {
  required_version = ">= 1.13.0"

  required_providers {
    random = {
      source  = "api.registry.lan/my-org/random" # The provider we just created
      version = "3.9.0"
    }
  }

  # Configure the HTTP backend to use our custom API for state management
  backend "http" {
    address        = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    lock_address   = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    unlock_address = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    lock_method    = "LOCK"
    unlock_method  = "UNLOCK"
  }
}
```

```hcl
# main.tf
module "naming" {
  source  = "api.registry.lan/my-org/naming/azure"
  version = "0.0.1"

  # Module configuration
  # Add your module inputs here
  suffix = [ "test" ]
}

output "analysis_services_server" {
  value     = module.naming.analysis_services_server
}
```

10. Execute:

```bash
terraform init
terraform apply -auto-approve
```

11. Once it finishes, check the TF state in [TF States](https://registry.lan/tfstate). It should show a deployment called `naming.tfstate`.
