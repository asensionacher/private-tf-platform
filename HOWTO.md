# HOW TO

This file provides a full example on how to use this project, with a private provider and module.

## Deployment

1. Clone the repo:

``` bash
git clone https://github.com/asensionacher/private-tf-platform.git
```

2. Create random passwords for encryption and Postgres:

``` bash
openssl rand -base64 32 # For encryption
openssl rand -base64 24 # For Postgres password
```

3. Copy `.env.example` to a new file called `.env` and replace the placeholder values with the keys generated by `openssl rand`.
4. Add a `REGISTRY_HOST` value in `.env` if you want a different one, or keep the default (in this example we will use `registry.lan`).
5. Create HTTPS certs if you don't have them by running [gen-certs.sh](./scripts/gen-certs.sh). These certificates will be saved in the `nginx/certs` folder.
6. Trust the CA certificate on every machine that will access the registry (the server and any machine running Terraform or OpenTofu). Copy `nginx/certs/ca.crt` to each machine and run the appropriate command:

   **Arch / CachyOS**
   ```bash
   sudo trust anchor --store ca.crt && sudo update-ca-trust
   ```

   **Debian / Ubuntu**
   ```bash
   sudo cp ca.crt /usr/local/share/ca-certificates/iac-registry-ca.crt
   sudo update-ca-certificates
   ```

   **RHEL / Fedora / CentOS**
   ```bash
   sudo cp ca.crt /etc/pki/ca-trust/source/anchors/iac-registry-ca.crt
   sudo update-ca-trust extract
   ```

   **macOS**
   ```bash
   sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca.crt
   ```

   **Windows** (run in an elevated PowerShell)
   ```powershell
   Import-Certificate -FilePath ca.crt -CertStoreLocation Cert:\LocalMachine\Root
   ```

7. Add the hostnames to your `/etc/hosts` file (Linux/macOS) or `C:\Windows\System32\drivers\etc\hosts` (Windows), where `server-ip` can be `127.0.0.1` or the private IP of the machine running nginx. This should be done on the machine that will run `Terraform` or `OpenTofu`:

```
server-ip registry.lan  api.registry.lan  tf.registry.lan
```

8. Start Docker Compose using:

```bash
docker compose up -d --build
```

9. Once it finishes, open a browser and navigate to [https://registry.lan](https://registry.lan).

## Using the platform

Now we will show an example on how to use a private provider and a private module.

1. Log in to the web UI at [https://registry.lan](https://registry.lan) with the default credentials `admin` / `admin` (change these in production via the **Users** page).
2. Create a private namespace for your org in Namespaces. We will create one called `my-org` and keep it private.
3. Create a new API key and save it to the clipboard.
4. On the machine that will run `Terraform` or `OpenTofu`, create a file called `~/.terraformrc` (Terraform) or `~/.tofurc` (OpenTofu) with the following content, where `<api-key-from-the-web-ui>` is the key you copied and `registry.lan` is your `REGISTRY_HOST`:

```hcl
host "api.registry.lan" {
  services = {
    "providers.v1" = "https://api.registry.lan/v1/providers/"
    "modules.v1"   = "https://api.registry.lan/v1/modules/"
  }
}

credentials "api.registry.lan" {
  token = "<api-key-from-the-web-ui>"
}
```

5. Create a new provider with the following values:
    1. Namespace: my-org (or your new private namespace).
    2. Provider name: terraform-provider-random
    3. Git repository URL: https://github.com/hashicorp/terraform-provider-random
6. Once the tags are synced, click the visibility toggle (eye icon) next to version 3.9.0 to publish it.
7. Click on the version (now shown in green) and upload the provider binary that matches the OS and architecture of the machine running Terraform. In this example that is `Linux AMD64`, downloadable from [terraform-provider-random_3.9.0_linux_amd64.zip](https://releases.hashicorp.com/terraform-provider-random/3.9.0/terraform-provider-random_3.9.0_linux_amd64.zip).
8. Create a new module with the following values:
    1. Namespace: my-org (or your new private namespace).
    2. Module Name: naming
    3. Provider: azure
    4. Git repository URL: https://github.com/asensionacher/terraform-azurerm-naming
9. Go inside the module and click the visibility toggle (eye icon) next to tag `v0.0.1` to publish that module version.
10. Create a folder on your machine with the following files:

```hcl
# terraform.tf
terraform {
  required_version = ">= 1.13.0"

  required_providers {
    random = {
      source  = "api.registry.lan/my-org/random" # The provider we just created
      version = "3.9.0"
    }
  }

  # Configure the HTTP backend to use our custom API for state management.
  # Credentials are passed via environment variables — never hardcode them in .tf files.
  # Set TF_HTTP_USERNAME and TF_HTTP_PASSWORD in your shell before running terraform/tofu.
  backend "http" {
    address        = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    lock_address   = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    unlock_address = "https://tf.registry.lan/api/tfstate/naming.tfstate"
    lock_method    = "LOCK"
    unlock_method  = "UNLOCK"
  }
}
```

```hcl
# main.tf
module "naming" {
  source  = "api.registry.lan/my-org/naming/azure"
  version = "0.0.1"

  # Module configuration
  # Add your module inputs here
  suffix = [ "test" ]
}

output "analysis_services_server" {
  value     = module.naming.analysis_services_server
}
```

11. Export your credentials as environment variables, then execute. Never put credentials directly in `.tf` files — they would end up in version control.

```bash
export TF_HTTP_USERNAME="admin"
export TF_HTTP_PASSWORD="admin"
terraform init
terraform apply -auto-approve
```

12. Once it finishes, check the TF state in [TF States](https://registry.lan/tfstate).
